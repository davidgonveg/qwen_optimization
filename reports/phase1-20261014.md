Fecha: 14 de octubre de 2026. **Puesta en marcha completada; calidad aún sin evaluar formalmente.** Las cuatro peticiones terminaron con `done=true`, `done_reason=stop`, sin errores ni truncamientos. La respuesta de cálculo fue incorrecta y se conserva intacta.

## Artefacto y entorno

- Modelo: `qwen3.8:27b`, GGUF Q4_K_M, familia arquitectónica `qwen35`, 27.3B comunicados por Ollama. No se sustituyó por Qwen3.5.
- Digest ejecutado: `sha256:aaee06c39dcf2437cde036998d960e1fc1494b8191be7cc9657d01e509097813`.
- Pesos de lenguaje: 16.810.714.464 bytes; proyector BF16: 931.146.016 bytes. Artefacto completo: 17.741.872.154 bytes (17,74 GB / 16,52 GiB).
- Licencia Apache-2.0. Fuente oficial: [Qwen/Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B), revisión consultada `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`. El commit fuente exacto usado para el GGUF no está demostrado.
- Runtime: Ollama 0.40.3, backend llamacpp/CUDA, driver NVIDIA 591.86. El config del artefacto exige Ollama 0.32.12; se cumple.
- Equipo: RTX 3060 de 12.288 MiB; Ryzen 5 5500, 6 núcleos/12 procesadores lógicos; RAM visible 31,87 GiB. E: tenía unos 1,43 TB libres. PowerShell 7.6.5; herramientas auxiliares existentes en `compatibility.json`. No se instalaron paquetes, Python, WSL ni Docker.
- Descarga: 260,76 segundos, registrada entre 17:27:49 y 17:32:10, hora de Madrid. Ollama verificó SHA256. La verificación posterior sin redescargar pesos terminó correctamente.

La [ficha de Ollama](https://ollama.com/library/qwen3.8:27b) incluye una variante MLX con otro digest. Se fijó el manifiesto **GGUF** del registro. Ollama añade al manifiesto local dos capas de procedencia: su hash `b45285c1…` difiere del remoto. El blob original conserva el hash fijado, y las cuatro capas originales y el config coinciden. El comprobador valida estas evidencias; no usa la etiqueta mutable como única identificación.

## Configuración reproducible

Ver `configs/reference.json` y los comandos de `README.md`. Instancia separada en `127.0.0.1:11435`, almacén `models/ollama`, concurrencia 1, contexto 2.048, salida máxima 256, `think=false`, semilla 42 y keep-alive de 5 minutos. Temperatura 0,7; top_p 0,8; top_k 20; min_p 0; presence_penalty 1,5; repeat_penalty 1. Estos parámetros de muestreo siguen la recomendación no-thinking de la ficha de Qwen.

El artefacto hereda `draft_num_predict=4`: el runtime activa MTP (`draft-mtp`), 6 hilos, cachés f16 y Flash Attention según su log. No se ajustaron como experimento. Aunque el entorno del servidor muestra `OLLAMA_FLASH_ATTENTION=false`, el backend registra Flash Attention habilitada; se documenta el comportamiento observado. El reparto automático deja **31/66 capas en GPU**. Buffers del modelo principal: CUDA 7.640,48 MiB y host 8.380,99 MiB; hay buffers adicionales de KV, estado recurrente, proyector, MTP y cómputo.

La API `/api/ps` comunica `size_vram=8.753.407.588` bytes y `size=18.100.109.963` bytes para el modelo cargado, contexto 2.048. Son contadores del runtime; no equivalen al uso total del dispositivo ni al working set del proceso. Los scripts restauran el entorno del proceso que los lanza y no cambian el almacén global ni variables persistentes del usuario.
